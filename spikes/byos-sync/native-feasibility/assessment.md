# Candidate assessment for lead review

Increasing the receiver batch to 100 fixes the exact thirty-document tie fixture, but it does not satisfy all of C3. H100 is a separate discovery counterexample: the native receiver has the old body while the full latest remote body is visible, even after two same-ID restarts and two more same-ID restarts supplying the supported initial checkpoint. A genuinely separate database retrieves that exact latest body. The fresh database remains a diagnostic control, never a substitute for the failed existing receiver.

T10's 16/30 result follows the published downstream query. `rxdb/src/plugins/replication-google-drive/downstream.ts:53` adds `modifiedTime >= checkpoint.modifiedTime`; lines 62–67 request only `batchSize + 6`, ordered by time/name, without nextPageToken. Lines 90–94 filter already-seen names only after receiving that fixed prefix and slice to batchSize. At batch 10, the first 10 advance the checkpoint; the next query exposes only six further names within the same 16-name prefix; the next call filters the entire prefix away. T100 requests 106 and receives all 30, as the complete listing/content traces demonstrate. A larger finite batch proves this bounded tie fixture only, not an unlimited tie set.

H100 isolates the temporal problem independently of tie cardinality. The old edit time is `2026-10-24T09:19:55.994Z`; the newer edit and persisted receiver checkpoint are `2026-10-24T09:19:56.009Z`. The older file is hidden only during the receiver's two hidden-old rounds. Direct inventories show it restored with unchanged modifiedTime, version and full latest body. Thereafter native query lower bounds remain above its modifiedTime. No batch size can cause that lower-bound query to include a strictly older file. The two documents suffice, and T100's positive tie result excludes thirty-way tie size as an explanation for H100.

Same-ID cancellation/recreation retains native replication metadata. `rxdb/src/plugins/replication/index.ts` constructs metadata collection identity from collection and replicationIdentifier; cancellation closes replication rather than deleting that metadata. `rxdb/src/replication-protocol/downstream.ts:53` applies `initialCheckpoint.downstream` only when no stored down checkpoint exists. H100's recorded actual option includes epoch-1970/empty-seen, while the persisted checkpoint and request lower bounds remain at the newer edit. `replication-protocol/checkpoint.ts` loads stored checkpoints and writes subsequent stacked checkpoints; it offers no public cursor rewind in this contract. Source copies and matching CJS hashes are in every actual run's pre/post source archives.

The explored supported candidates are batch 10 vs 100, explicit synchronization, same-identifier native lifecycle restart, supported initialCheckpoint on the same receiver, and a separate fresh-database diagnostic. Retry/transaction timing options govern transaction acquisition or retry scheduling; extra successful sync calls use the same persisted lower bound. Pull modifiers run on returned documents, and device-local protection can retain acknowledged local bodies but cannot reconstruct an unseen remote body. These source arguments explain why those option families do not repair the demonstrated old-hidden-edit schedule. Live signaling/leadership and unattended product behavior are outside this explicit-sync protocol; no affirmative claim is made for them.

Unexplored approaches involving changed replication identity, metadata reset/removal, an application inventory/backfill scanner, altered native query/checkpoint policy, a custom conflict handler, native fork/version/provider, or new architecture are not demonstrated solutions within this frozen same-receiver/native-discovery contract. Their consideration would need an explicit scope/contract decision. This is a bounded negative candidate assessment under the faithful shared mock's adversarial visibility assumption, not proof against every possible application design or a claim about real Google consistency.

C2 remains INCONCLUSIVE for successful mutation with lost response; existing advance/verified-cleanup positives do not fill that interval.
