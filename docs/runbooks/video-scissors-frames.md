# Video Scissors PNG frames (#152)

The website works locally without a ChatGPT connection. Select a supported MP4,
enter original-source seconds, and click **Capture Current Frame**, then
**Download PNG**. **Use Original Preview Time** copies the original preview's
playhead; it is disabled for an edited preview because output time is not source
time. The latest successful PNG is session memory only, separate from MP4 output
and one-level Undo. Selecting another source clears it. Failure/cancellation keeps
it. Old object URLs are revoked on replacement/source change/disposal.

## Decode decision

Use the existing FFmpeg WASM runtime and original File, not a second production
Canvas/video decoder. Canvas would avoid PNG encoding in WASM but needs separate
media-element load/seek/frame-ready synchronization and codec/rotation semantics.
The editor already depends on FFmpeg inspection and decoding, with isolated worker
termination on abort. Extraction uses the same busy/cancel fence, no new package,
no service and no persistent filesystem. Decode from source origin with output
seeking, select first real video (`0:V:0`, excluding attached pictures), encode one
PNG without scaling. Extend the final decoded frame across EOF with `tpad` so a
valid source-duration timestamp also works in a variable-rate or long-audio tail.

The convention is the first frame at/after the requested source time, or the last
frame at EOF. Where constant-rate video spans the requested time, error is at
most one source frame period. Do not claim that bound across audio-only tails
or variable-rate gaps; the next decoded presentation timestamp can
be farther away. Timestamps must be finite, nonnegative and strictly before source
duration. Source constraints remain H.264/AAC MP4, 100 MB, 300 s, 1080p/30 fps.

Run `npm run prepare:video-scissors`, `npm run build`, then
`node scripts/video-scissors-frames.e2e.mjs` (desktop Chrome, or set
`VIDEO_SCISSORS_CHROME`). The fixture is generated by actual browser WASM and never
saved. Per-frame grayscale identifies original frame numbers; keyframes are one
second apart. Evidence contains dimensions, frame identity, source hash, browser
version and bounded request counts under ignored `.deploy/video-scissors-frames/`.
No media payload or credential is retained there. Unit tests cover late completion,
source switch, cancellation/failure, URL lifecycle, stale version and MP4 history.

## D control and release qualification

Only D advertises `extractframe` with strict
`{ operationId, generation, version, timeSeconds }`. It requires existing
`video:edit` authorization. D's project authority uses existing owned, expiring,
revocable queue/claim/report/status receipts, cancellation and no replay. Admission
checks source duration. `queued`/`claimed` are not completion: poll `status` for
`completed`, then direct the user to the website's **Download PNG**. No PNG, file
name/path, Blob URL, pixel data or image metadata is added to Worker metadata.
Remote frame publication rechecks the exact connection/lease after decoding,
so a throttled background expiry timer cannot publish a late PNG.
Extraction does not move the latest MP4 Undo target. A/B do not advertise the tool;
their mailbox rejects its command kind. Shared browser parsing supports D without
switching connection origins or activating any service.

D remains experimental. `wrangler.d-staging.template.jsonc` still has
`EXPERIMENT_ENABLED=false` and placeholder bindings; `index-d.ts` fails closed
unless explicitly enabled. No activation, Cloudflare deployment, production switch,
merge or issue closure is part of this implementation. Existing D staging
qualification in `workers/video-scissors-mcp/docs/stateless-do-candidate.md` remains
a separate gate. Local Miniflare OAuth/MCP and Chrome tests are **not real ChatGPT
Web evidence**. Remaining acceptance: orchestrator review/merge; exact staging
candidate deployment and separately authorized D activation/qualification; real
ChatGPT Web OAuth → extractframe → browser completion → preview/download with
redacted control-only audit; Founder acceptance and independent production release
authorization. Keep #152 open pending those gates. Rollback is reverting this
feature's source PR/artifact under the existing release contract; no resources or
schema migration are introduced.
